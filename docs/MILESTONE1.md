# Milestone 1: select a word, see its article

**Goal:** on any web page, the user selects a German noun (inflected or not), asks
ArtikelFinder, and sees the article(s), the lemma, what the selected form is
(case/number), and how certain that is. Nothing else: no accounts, no AI, no server,
no compound guessing (that is Step F).

## User flow

1. Select a word, then **right-click → "Artikel für „Tischen"“** or press **Alt+Shift+A**.
2. A small bubble appears next to the selection:

```
der Tisch                         ✓ 2 sources agree
Tischen = dative plural           plural: die Tische
▸ Declension                      (expands to the 8-cell table)
```

3. Esc, a click outside, or scrolling closes it.

Several candidates are listed one per line (der Leiter / die Leiter; der/die Jugendliche).
An unknown word says so plainly ("Not in the dictionary"). It never guesses.

## Decisions

| Decision | Choice | Why / rejected alternative |
|---|---|---|
| Trigger | Context menu + keyboard shortcut | Needs only `activeTab`, so Chrome shows **no** "read all your data on all websites" warning. Auto-bubble on double-click needs a content script on every page (broad host permission, runs on every page, interferes with sites). It can come later as an opt-in via `optional_host_permissions`. |
| Permissions | `contextMenus`, `activeTab`, `scripting` | Least privilege. No host permissions. |
| Where lookup runs | Background service worker | Data files do not have to be `web_accessible_resources`, so web pages cannot probe or fingerprint them. The worker caches recent shards while alive. |
| Data loading | `fetch(chrome.runtime.getURL("data/i/143.json"))` per lookup | See `pipeline/runtime_format.py`: the worker is short-lived, so nothing is preloaded. |
| Bubble rendering | Injected script, **closed Shadow DOM**, `textContent` only | Page CSS cannot break the bubble, and the bubble cannot break the page. Data comes from Wikidata (anyone can edit it), so it is never inserted as HTML. |
| Language / tooling | Plain JavaScript ES modules, no bundler, no framework, no TypeScript build | ~4 small files; MV3 loads ES modules natively. JSDoc types, which `tsc --checkJs` can check later without a build step. React would solve nothing here. |
| UI language | English, with German grammar terms in parentheses where useful | Target users are learners. `chrome.i18n` can add German later without code changes. |
| Browsers | Chrome / Edge (Chromium MV3) | Firefox runs MV3 background code as event pages, not service workers; revisit after M1. |

## Input normalization (`normalize.js`)

Selected text → ordered list of keys to try; first key with results wins:

1. Trim; strip surrounding punctuation and quotes („Tisch“, → Tisch); NFC-normalize.
2. More than one word → "select a single word" (multi-word nouns are out of M1).
3. Try exact, then capitalized for lower-case input (tisch → Tisch), then capitalized for
   ALL CAPS (TISCH → Tisch). The bubble says when the case was changed.

Known limit, stated not hidden: ALL-CAPS "STRASSE" cannot be mapped back to "Straße".

## What the bubble shows, per candidate

| Field | Source |
|---|---|
| Article(s) + lemma | gender mask → der/die/das; several genders → "der/die" + "both are used" |
| Reading of the selected form | cells recomputed from the paradigm: "dative plural", "genitive singular / all plural cases" |
| Plural | NOM.PL cell, if present |
| Certainty | `agree` → "2 sources agree"; `filled`, `wikidata`, `wikidata_only` → "1 source (Wikidata)"; `unverified` → "1 source (UniMorph)"; `conflict` → "sources disagree" + the other source's article; `unknown` → "gender unknown" |
| Declension table | collapsed `<details>`, 8 cells |

## Testing

- **Reader parity (most important):** Python writes golden lookups (all spot-check words
  plus a few thousand random surfaces) to `build/golden.json`; `extension/test` runs the
  JS reader over the same data and must match exactly. Also the FNV-1a golden hashes from
  `tests/test_runtime_format.py`.
- **Normalization:** unit tests for punctuation, quotes, case changes, multi-word input.
- **Rendering:** the bubble's text model (what lines to show for a candidate list) is a pure
  function, unit-tested; the DOM part stays thin.
- **End to end:** manual checklist in Chrome for M1 (load unpacked, the spot-check words,
  a page with hostile CSS). Automated browser tests (Playwright loading the unpacked
  extension) only if manual checks start to cost real time; it adds a ~150 MB dependency.
